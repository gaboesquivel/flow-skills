# Architecture Decision Records

No ADRs have been accepted yet.

Use a record for a significant technical choice involving boundaries, integrations, constraints, or consequential tradeoffs. Keep routine implementation details in code.

Provisional naming: `0001-short-decision-name.md`.

A useful record contains status (proposed, accepted, rejected, or superseded), date, context and evidence, decision, alternatives, consequences, and links to affected documents. Record acceptance evidence when a decision is accepted. A replacement should link the earlier record so its history remains understandable.

Accepted architectural decisions update ARCHITECTURE.md. The record preserves rationale; the living document describes the resulting current position.
