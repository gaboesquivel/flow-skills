# Flow Skills website

Status: planning, started 2026-10-20. Website implementation has not started.

## Outcome and scope

Plan a landing page that helps solo founders and small technical teams understand Flow, its principles, and how its practices connect. The page should make the intended value clear while accurately representing the methodology and skills' development status.

This initiative owns page structure, copy drafts, and website planning. PRODUCT.md owns product direction; the principles and methodology remain authoritative for their content. No technology, hosting, domain, or implementation approach is selected.

## Accepted direction

- Lead with “Skills for Agentic Product Engineers.”
- Use the supporting description below as the current working copy, accepted for now.
- Follow the introduction with principles, then workflow.
- Use Addy Osmani's skills website as the primary layout and presentation reference; Matt Pocock remains a secondary reference.
- Keep the look and feel related to gaboesquivel.com and use the same palette. Exact visual tokens still need inspection; no colors or typography have been inferred from extracted page text.
- Find a distinct expression for Flow rather than reproduce the reference's presentation.

## Working hero copy

**Headline:** Skills for Agentic Product Engineers

**Supporting description / value proposition:** An open-source toolkit grounded in Lean Startup principles. Helping solo founders and small teams discover what matters, build with purpose, and learn from what they ship.

The description expresses intended value, not current skill availability. Show development status separately while skills are not implemented.

## Page outline

1. **Introduction:** headline and supporting description. Mission and motto placement remain open; avoid repeating the same promise in several adjacent lines.
2. **Principles:** draw from [the principles draft](../principles.md): validation, observability, agentic, lean, and velocity. Preserve room for exploration without presenting every principle as a checklist.
3. **Workflow:** explain how discovery, refinement, delivery, and learning connect, using [the methodology](../methodology.md). Stage names and visual form remain proposals, not a new mandatory sequence or implemented commands.

Later sections, navigation, calls to action, and a future skill catalog remain open. Do not show installation instructions or availability claims before they are supported.

### Differentiator, mission, and motto

Proposed differentiator: Flow connects choosing worthwhile work, building it, and learning from its outcomes while preserving alignment between product, design, architecture, and implementation. Show that connection through one concrete example or an iterative workflow; visual treatment remains open.

Proposed mission wording: Help people turn ideas into useful products through purposeful building and continuous learning.

“Build what matters” remains a candidate motto, not an adopted slogan. The headline identifies the audience; the value proposition explains the benefit; the mission states why Flow exists; a motto is its short memorable expression.

## Assumptions and validation
