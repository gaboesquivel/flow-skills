# Native session capabilities — 2026-10-31

Candidate evidence for [spec 045](../specs/045-native-observable-sessions.md), not an adopted execution contract. Reviewed repository base: `a5373e894b488b375984d56ff3e794edc6e77360`. Official pages inspected on 2026-10-31; no host session was launched or resumed in this research.

| Source | Documented evidence | Limit |
| --- | --- | --- |
| [Claude Code CLI reference](https://code.claude.com/docs/en/cli-reference) | Resume by ID/name; `--fork-session` creates a new ID on resume; `claude agents` exposes monitoring of background sessions. | Installed version and available agent controls need verification. A command's existence does not guarantee UI linkage. |
| [Claude Code session management](https://code.claude.com/docs/en/sessions) | Naming, resumption, branching and transcript export/storage are documented. | Retention and cross-surface access need a live check; export is not required by this proposal. |

The page warns that a fork can still share files. | Desktop visibility does not cover every CLI/cloud session. A parent-child tree and agent-driven creation on the intended surface remain unverified. |
| Claude Code Desktop session tools (observed in a Desktop session on 2026-10-31) | The agent's tool list includes starting a session (fresh or forked, own worktree or shared), listing sessions it started as linked, messaging a session by ID and handing its own task off. The host's guidance sends pieces of one task to subagents and reserves sessions for separate tasks or the user's request; otherwise the agent proposes a session the user starts with one click. | Tool exposure was read, not exercised: no child session was started, resumed or inspected. Guidance can change between app versions. |
| Claude Code Desktop session and pull request tools (re-read later on 2026-10-31, for [spec 052](../specs/052-native-session-integration.md)) | After an accepted plan, independent steps are proposed as session cards (at most four) while the agent starts its own; linked sessions wake the parent when they end a turn, quoting each latest report to 400 characters, and the guidance calls that report evidence, not proof; branches from worktree sessions merge only when the user says so, named by `refs/heads/…`; a bound pull request wakes the session on checks, conflicts, and comments, and the agent must not poll CI; a native hand-off moves an interrupted task to its own session; `sync_with_base_branch` updates app-made worktrees. | Read from the tool guidance, not exercised. Guidance can change between app versions. |
| [Cursor CLI slash commands](https://cursor.com/docs/cli/reference/slash-commands) | `/fork` and `/resume` are documented. | This does not establish an agent-callable API, Desktop parity, transcript access or a parent-child tree. Cursor's IDE agent surfaces were not inspected. |

The design inference is to prefer reachable native capabilities while testing visibility, isolation and resumption separately. Neither a subagent trace nor a fork alone proves an independent, observable writing session. The requested parent-child visualization remains a native-first requirement with an explicit concise-reference fallback, never a reason to build a new UI.
