# E43 live comparison (2026-10-31)

## Scope

One run per condition of [E43](../tasks/E43-task.md) ([rubric](../rubrics/E43-rubric.md)) for [spec 047](../../../docs/specs/047-shared-language-test-first.md): the skills before spec 047 (`0f60fe8`) against the skills after it (`521bdfc`), on the [lending desk fixture](../../fixtures/e43-shared-language/README.md).

## Conditions

- Host: Claude Code desktop. Each run was a subagent on `claude-sonnet-5-5`, one fresh fixture repository per run, local delivery, no remote.
- Headless `claude -p` runs with `--setting-sources project` loaded only the project's skills, but the host's auto-mode safety check refused to launch them with shell access. Subagents were used instead: each was told to read skills only from its fixture's `.claude/skills/` and not to use the Skill tool. A subagent could not get answers to questions; a question would end the run.
- Every test command ran through a wrapper that logged the command, its exit code, and which source files (`lib`, `routes`, `mcp`, `public`) had changed at that moment. The test-order verdicts come from those logs, not from the agents' reports.
- Independent review was out of scope: each run was told to self-check and label it single-agent.

## Verdicts against spec 047

1. **Glossary term, no question, no new document:** satisfied for both versions. It does not discriminate: the fixture's code already says "hold", so both agents followed it.
2. **Contract check first:** satisfied after 047, unmet before. This is the clear effect.
3. **Focused then full once; no UI test; preview checked:** partly met. No UI test in either version and the preview was checked after 047. But both versions ran the full suite more than once, and the request 2 run after 047 used it as its only test loop (five runs).
4. **One question on the 7-day vs 3-day conflict:** unmet for both. Both reported the conflict and left it alone. The extension did not change the expiry rule, so not asking is consistent with the Shared language rule ("only when … the meaning changes the behavior"). The step as written expects a question the rule does not require.
5. **README typo:** satisfied for both.
6. **Comparison:** this record. One run per condition; small differences (suite runs) are within noise.

## Findings

1. Contract test-first works as written and is the change spec 047 makes observable.
2. "Focused, then full once" is not followed. The agent uses `npm test` both as the red check and as its working loop. Candidate fix: name the focused command in the red step ("run only that file"), or have the fixture's `AGENTS.md` make the focused command the obvious first row.
3. Step 4 and request 1's vocabulary check do not discriminate. Request 2 should change expiry (for example "holds should last longer") so the conflict changes behavior. Request 1 needs code that is silent on the term, so the glossary is the only source.
4. The evidence is weaker than a host run. Subagents read skills from files instead of loading them, and each condition ran once on one model.

`live_skill_execution` for E43 stays `not_executed` until a host run loads the skills natively.
