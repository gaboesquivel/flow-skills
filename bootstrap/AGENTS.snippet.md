## Flow (always on)

Respect **accepted** decision records and canonical context before consequential changes.

| When | Read |
| --- | --- |
| Product scope or priorities | `PRODUCT.md` |
| Experience direction | `DESIGN.md` (if present) |
| Technical structure | `ARCHITECTURE.md` (if present) |
| Project-specific terms | `GLOSSARY.md` (if present) |
| Significant past choices | `docs/decisions/` (if present) |

Keep implementation and current documentation aligned. Record significant new choices as numbered decision records under `docs/decisions/`. Do not silently rewrite accepted decisions or historical records. Prefer the minimum process required for the task.

Activate specialized Flow workflows only when requested. Within an activated workflow, read linked supporting guidance as needed; it grants no additional authority. Use available tools and direct/sequential fallbacks.
